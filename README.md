# Graph RAG on arXiv abstracts

Hybrid retrieval over a Neo4j knowledge graph: vector search finds relevant chunks, then graph
traversal expands to related entities and neighbouring chunks. Answers are generated by Groq and
cite chunk ids.

## Pipeline
1. `data.py` – load `data/raw/corpus.csv`, stratified train/test split, recursive chunking.
2. `models.py` – Pydantic schemas + Instructor/Groq extraction of entities and relationships.
3. `graph.py` – Neo4j schema, MERGE-based upserts, local embeddings, vector index.
4. `retrieval.py` – vector search + graph expansion + grounded answer generation.

Graph schema: `(Document)-[:HAS_CHUNK]->(Chunk)-[:MENTIONS]->(Entity)-[:REL]->(Entity)`.

## Setup
```bash
python3.10 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
docker run -d --name neo4j-graphrag -p 7474:7474 -p 7687:7687 \
  -e NEO4J_AUTH=neo4j/graphrag_local_pw -v $HOME/neo4j-graphrag/data:/data neo4j:5
cp .env.example .env   # then set GROQ_API_KEY
```

## Web app
```bash
uvicorn graphrag.api:app --port 8000      # then open http://localhost:8000
```
Visitors upload `.txt`, `.md` or `.pdf` files and ask questions. Each visitor gets a private workspace
(an unguessable cookie); the shared demo corpus is searchable by everyone. Limits and daily budgets are
settings (see `graphrag/config.py`). `/docs` lists the HTTP API. See DEPLOYMENT.md before making it public.

## Run
```bash
python -m scripts.prepare_corpus --per-category 100   # build data/raw/corpus.csv
python -m scripts.build_graph --reset                 # extract + embed + load (resumable)
python -m scripts.ask "How is homomorphic encryption used to protect biometric data?" --show-context
python -m scripts.make_eval_set --n 40                # generate eval questions
python -m scripts.evaluate                            # hit@k, MRR, vector vs vector+graph
python -m scripts.cleanup_workspaces --dry-run        # idle visitor workspaces
```

## Notes
- Extraction results are cached in `data/processed/extractions.jsonl`; rerun `build_graph`
  (without `--reset`) to resume after an interruption or a Groq daily-quota stop.
- Groq free tier has a per-model daily token limit. Use `GROQ_MODEL` for extraction and
  `ANSWER_MODEL` for answering so they draw on different quotas.
- Only the train split is indexed; the evaluation samples indexed documents.

## Tests
```bash
pip install -r requirements-dev.txt
python -m pytest                      # unit tests only; integration tests are skipped
```
Integration tests run against a throwaway Neo4j and **wipe it**. Never point them at your real graph; the
suite refuses any database that already holds non-test data.
```bash
docker run -d --name neo4j-test -p 7688:7687 -e NEO4J_AUTH=neo4j/testpassword neo4j:5
TEST_NEO4J_URI=bolt://localhost:7688 python -m pytest
```
The LLM and the embedding model are mocked, so no API quota is spent. CI (`.github/workflows/ci.yml`) runs the
same commands against a Neo4j service container.
